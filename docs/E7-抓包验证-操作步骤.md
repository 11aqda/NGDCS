## 2. ⚠️ 实测记录：安装这件事上有三个坑（都踩过了，写下来省时间）

### 坑 1：Wireshark 的安装器用**静默参数**调 Npcap，而且关掉了回环

Wireshark 安装过程中的 "Installing" 页会显示实际执行的命令行：

```
Execute: "D:\Tools\Wireshark\npcap-1.88.exe" /winpcap_mode=no /loopback_support=no
```

看到 `/loopback_support=no` 时我们一度以为回环就此废了。**实际上没影响**（见坑 3）。

### 坑 2：这次静默安装**静默失败了**，只留一个空壳

症状：`dumpcap -D` 报 `Unable to load Npcap (wpcap.dll)`。

| 检查项 | 失败时的状态 |
|---|---|
| `C:\Program Files\Npcap` | 只有一个 **0 字节的 `install.log`**（残骸） |
| `C:\Windows\System32\Npcap\wpcap.dll` | ❌ 没有 |
| `C:\Windows\System32\drivers\npcap.sys` | ❌ 没有 |
| `npcap` 服务 | ❌ 没注册 |
| 程序列表里的 Npcap 条目 | ❌ 没有（只有 Wireshark） |

**八成原因：UAC 弹窗被拒**（装内核驱动要管理员）。**修法**：手动跑
`D:\Tools\Wireshark\npcap-1.88.exe`（安装器把它留在安装目录了），这次在 UAC 上点「是」。

> ⚠️ 注意：`C:\Program Files\Npcap` 这个**空目录**会让 Npcap 安装器以为"已安装"。
> 但因为这个残留只有 0 字节的 `install.log`、注册表/服务/驱动全无，
> 手动跑一次仍会走正常安装流程，**不必先删目录**。

### 坑 3：**Npcap 1.88 没有 `Support loopback traffic` 复选框**（重要更正）

网上（包括本文初稿）都说要在 Npcap 的 Installation Options 页勾
`Support loopback traffic ("Npcap Loopback Adapter")`。**Npcap 1.88 上没有这一项** ——
那一页只有三个复选框：

```
☐ Restrict Npcap driver's access to Administrators only
☐ Support raw 802.11 traffic (and monitor mode) for wireless adapters
☑ Install Npcap in WinPcap API-compatible Mode
```

**原因：新版 Npcap 把回环支持做进驱动了**，`\Device\NPF_Loopback` 由驱动默认创建，
不再需要单独的 "Npcap Loopback Adapter" 那个旧机制。

**所以正确的做法是**：勾 `WinPcap API-compatible Mode` → Install → 用 `dumpcap -D`
**验证** `NPF_Loopback` 在不在，而不是去界面上找那个不存在的复选框。

## 3. 为什么这件事值得单独记：要抓的是**回环流量**

E9 / E1 等实验全部跑在 `127.0.0.1` 上。Windows 上 Wireshark 靠 **Npcap** 抓包，
如果 Npcap 装不上或回环没启用，会出现
「Wireshark 一切正常、就是一个包都抓不到」的现象，然后让人误以为是代码问题。

**更麻烦的是：换成局域网 IP 也没用。** 这是本项目 D-016 的实测结论 ——
Windows 会把**发往本机地址的流量短路到回环**，根本不过网卡
（当时测到 16 MB 传输 1145.8 MB/s、网卡增量只有 0.001 MB）。

所以有两条路：

| 方案 | 做法 | 适用 |
|---|---|---|
| **A. 抓回环**（已打通，用这个） | 抓包时选「Adapter for loopback traffic capture」；Npcap 1.88 自带回环，无需额外勾选 | E7 的协议正确性验证（帧头 / 粘包 / 半包） |
| **B. 走 VMnet1** | 服务端跑宿主机，客户端跑 VMware 虚拟机 | 想要真实网卡流量；也是 E4/E5 弱网实验的前提 |

> 方案 A 对 E7 完全够用 —— E7 要证明的是「**我们实现的协议在字节层面正确**」，
> 而回环上看到的字节与真实网卡上看到的**逐字节相同**，只少一层链路层封装。

## 3. 安装步骤

### 3.1 下载

**⭐ 首选：清华 TUNA 镜像**（本项目一直用清华源装 pip，同一条路，校内通常快得多）

```
https://mirror.tuna.tsinghua.edu.cn/wireshark/win64/Wireshark-4.6.9-x64.exe
```

目录页：<https://mirror.tuna.tsinghua.edu.cn/wireshark/win64/>

- 该文件与官方发布**同一个**（93.4 MiB）
- 2026-10-26 实测：官方站 `wireshark.org` 只有 **30.4 KB/s**（93.4 MB 要 52 分钟），
  清华源快得多

**备选：官方站** <https://www.wireshark.org/download.html> → **Windows x64 Installer**

- `Npcap` **不用单独下载**，Wireshark 安装包自带
- 按项目惯例，安装包放 `D:\Tools`（与 Apifox / Redis 一致）

> 镜像目录里还有 `.msi`（76.7 MiB，更小）与 `WiresharkPortable64`，
> 但**建议统一用 `.exe`** —— 本文 §3.2 的选项界面按 `.exe` 写的。

### 3.2 安装时的选择（**已按 1.88 的实际界面更正**）

| 界面 | 怎么选 | 为什么 |
|---|---|---|
| Choose Components | ✅ Wireshark、✅ TShark | TShark 是命令行版，可用脚本核对帧头字节 |
| Choose Components | ⬜ External capture tools (extcap) | 抓 Android / SSH / Cisco 用，与本实验无关 |
| Choose Components | ⬜ USBPcap | 只抓 TCP，用不上 |
| Choose Install Location | **`D:\Tools\Wireshark`** | 按项目约定「工具装到 D:\」；路径无空格，调 `dumpcap` 方便 |
| Packet Capture | ✅ Install Npcap 1.88 | 没它抓不了包 |
| **Npcap Installation Options** | ✅ Install Npcap in WinPcap API-compatible Mode | 兼容性更好 |
| Npcap Installation Options | ⬜ Restrict Npcap driver's access to Administrators only | 随意；勾了就得每次用管理员开 |
| Npcap Installation Options | ⬜ Support raw 802.11 traffic | 抓 Wi-Fi 原始帧才用 |
| ~~Support loopback traffic~~ | **1.88 上不存在这一项**，见 §2 坑 3 | 回环是驱动内置的 |

> ⚠️ **Wireshark 安装器的 Npcap 步骤可能静默失败**（UAC 被拒），
> 表现是装完 `dumpcap -D` 报 `Unable to load Npcap`。
> 此时手动跑 `D:\Tools\Wireshark\npcap-1.88.exe` 补装（详见 §2 坑 2）。
>
> **实测装完不需要重启** —— 驱动当场加载。

### 3.3 验证（**这一步别跳**）

先别开图形界面，用命令行确认回环适配器在不在：

```powershell
& "D:\Tools\Wireshark\dumpcap.exe" -D
```

预期能看到：

```
5. \Device\NPF_Loopback (Adapter for loopback traffic capture)
```

- **有 `NPF_Loopback`** → 可以继续抓包
- **没有** → 先看是不是 `Unable to load Npcap`（那就是 Npcap 没装上，见 §2 坑 2），
  而不是去找那个不存在的回环复选框

> 这一步先确认，能避免"装完了才发现抓不到包"。

## 1. 它是什么

| 项 | 值 |
|---|---|
| **项目名** | 多人游戏服务端监控与数据分析平台 |
| **候选仓库名** | `ngdcs-observability`（**将来**若拆库时才用这个名字） |
| **定位** | **只读**的监控 / 复盘 / 实验分析控制台 |
| **明确不做** | 网页版游戏、聊天、账号体系运营后台、完整 CMS、任何协议改动 |

一句话：**「让服务端跑起来之后发生了什么」变得看得见** ——
不是把 `tools/plot.py` 的图搬到网页上。

---

## 2. 为什么它值得成为**第二个**求职项目

C/S 那个项目证明的是"**我能写对实时通信**"；
这个 Web 证明的是"**我能把一个系统观测、度量、诊断**"。
两者能力不重叠，才不会被看成一个项目的两个壳。

### 与现有 `tools/plot.py` 的区别（这是它存在的理由）

| 能力 | `tools/plot.py`（已有） | Web 平台（规划） |
|---|---|---|
| 出图 | ✅ 离线跑批、matplotlib 生图 | 网页交互、可按条件筛选重画 |
| **实时性** | ❌ 只能事后 | ✅ **在线人数 / 带宽 / tick 耗时的实时曲线** |
| **历史复盘** | ⚠️ 只能靠命令行参数 | ✅ **按实验条件（E1/E2/E4/…）筛选、多条对比** |
| **异常告警** | ❌ 无 | ✅ tick 超预算、断线率突增、带宽越界 → 告警 |
| 数据来源 | 指标 CSV | MySQL + Redis + CSV 归档 |

> **红线**：如果做出来只是"把 matplotlib 图贴到网页"，这两个项目就重复了，不如不做。
> 实时监控 / 历史复盘 / 异常告警 —— **至少要有两个真正做出来**。

## 3. 功能规划（MVP 边界）

### 3.1 实时监控（核心）

- 在线玩家数、每秒快照数、上行带宽、tick 耗时（p50/p95）
- 数据源：服务端**已有的**指标（`server/metrics.py` 每秒一行）+ WebSocket 推送
- 服务端只需**新增一个只读接口**，不改协议、不改 tick 逻辑

### 3.2 历史复盘（核心）

- 按 `scenario_id`（E1/E2/E4/…）筛选历史指标
- 多条件并列对比（例如 E5 的 10 Hz vs 30 Hz 摆在一张图里）
- 数据源：`data/server_metrics.csv` + `data/runs/*.json` 导入 MySQL

### 3.3 异常告警（加分项）

- 规则示例：`tick_ms_avg > 0.8 × 帧间隔`、`clients_connected` 骤降 50%、
  `bytes_out` 超出该场景历史均值 ±30%
- 触发后记录到 `alerts` 表并在页面上标红

### 3.4 **不做**（写下来防止膨胀）

- ❌ 网页里玩游戏（那会变成第三个项目，且没有价值）
- ❌ 聊天 / 好友 / 房间管理
- ❌ 完整的账号运营后台（复用毕设已有的 `auth_user` 即可）
- ❌ 任何对 `protocol/` 的改动

## 4. 技术选型（初步，开工时再定）

| 层 | 候选 | 理由 |
|---|---|---|
| 后端 | **Django**（复用毕设已有的 `webapp/`） | 已有 `auth_user` / `score_record` / Redis 排行榜，不用重造 |
| 实时推送 | Django Channels 或 SSE | 监控面板是**单向推送**，SSE 更简单；Channels 更通用 |
| 前端 | 原生 JS + 轻量图表库（uPlot / Chart.js） | 求职项目要能讲清"为什么选它"，不必上 React |
| 存储 | MySQL（历史指标、告警）+ Redis（实时缓存） | 与毕设一致，减少新依赖 |

### 5.1 现在做什么

### 5.3 仓库策略（重要：**现在不建第二个仓库**）

| 阶段 | 做法 |
|---|---|
| **现在** | **只维护一个仓库**（`NGDCS`），不新建第二个 `.git` |
| 做原型时 | 在当前仓库的 **`portfolio` 分支**的 **`web/` 目录**下开发 |
| 稳定后 | 如果确实需要独立仓库，用 **`git subtree split`** 或**单独 clone** 的方式拆出去，**保留历史，不复制 `.git`** |

> `ngdcs-observability` 是**未来**独立仓库的**候选名**，不是现在建。
> **现在不拆是时间问题，不是永远不拆** —— 这句话要写清楚，
> 免得半年后接手的人以为 Web 必须塞在本仓库里。

## 6. 求职时怎么讲（面试稿雏形）

| 面试官可能问 | 回答要点 |
|---|---|
| 这两个项目有什么关系？ | 一个是**被观测对象**（游戏服务端），一个是**观测者**（监控平台）。  
两者通过**同一份真实数据**连接，不是两个练习题。 |
| 为什么不用现成的（Prometheus/Grafana）？ | 毕设的指标是**游戏语义的**（tick 耗时拆成 sim/collision/ser/net、快照字节数、实体数），  
通用监控工具接不上；这里要做的是**领域指标的可视化与异常判定**。 |
| 指标怎么采集的？ | 服务端**每秒聚合一行**写 CSV（`server/metrics.py`），不逐帧打点 ——  
这是 E1/E2/E9 那套实验一直在用的机制。 |
| 实时性怎么保证？ | 只读接口 + 单向推送，不碰游戏的 tick 循环。 |

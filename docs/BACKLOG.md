## 使用规则

1. 冒出新想法 → **先写进本文件**
2. 每完成一个阶段，回来看一次，评估能否启动
3. 决定启动时：从本文件删除 → 写进 `01-系统架构.md` 的范围章节 → 更新 `PROGRESS.md` 与 `DECISIONS.md`

**为什么要有这个文件**：`PROGRESS.md §4.5` 定下的纪律是「预算已超支，不得再加新功能」。
本文件是那些想法的**缓冲区** —— 既不丢掉灵感，也不让它污染当前计划。

# Python 后端求职路线（2027 届）

> 目标：2027 年春招拿到 **Python 后端 / 后端平台 / 运维开发 / 测试开发** offer。
> 主项目：本毕设（C/S 实时通信系统），不另起炉灶。
> 制定：2026-10-21

---

## 0. 先认清时间

| 时间 | 事情 | 说明 |
|---|---|---|
| 2026 年 7–11 月 | **2027 届秋招** | 现在（10 月下旬）已接近尾声，仍有少量补录/中小厂 |
| 2026 年 10 月–2027 年 1 月 | **准备期** | 毕设核心 + 后端技能 + 项目打磨 + 简历 |
| 2027 年 1 月 | 春招提前批 | 部分公司开始 |
| 2027 年 2–4 月 | **春招主战场** | 每天投递 + 面试 + 复盘 |
| 2027 年 4–6 月 | 论文/答辩 | 与春招收尾重叠，提前写论文 |

**结论**：不要等“学完”再投。2 月之前必须有一份能投的简历和一个能讲的项目。

## 1. 目标岗位（不要只盯“Python 后端”）

优先级从高到低：

1. **Python 后端**（Django / FastAPI）
2. **后端平台 / 基础架构**（Python + Linux + 网络）
3. **运维开发 / DevOps**（你的网络工程背景很匹配）
4. **测试开发**（会写代码的测试，竞争相对小）
5. 传统企业数字化 / 外包（先上车，再跳）

语言不是壁垒。你的优势是：**网络 + Linux + Python + 一个真实的 C/S 项目**。

## 2. 能力优先级

### P0：不会就面不过

| 能力 | 学到什么程度 | 怎么证明 |
|---|---|---|
| Python | 语法、OOP、异常、生成器、装饰器、`async/await`、线程/进程、GIL | 能讲清毕设里的 asyncio 服务端 |
| Django + DRF | 项目/app、ORM、迁移、视图、序列化、认证/权限、中间件 | 毕设的登录 + 排行榜接口 |
| MySQL | SQL、JOIN、索引、事务、隔离级别、`EXPLAIN`、N+1 | 用户表、分数表、排行榜查询 |
| Redis | String/Hash/List/Set/ZSet、TTL、缓存穿透/雪崩、分布式锁 | 排行榜 ZSET + 会话缓存 |
| HTTP | 方法、状态码、Header、Cookie/Session/JWT、CORS、REST | 能画一次登录请求的完整链路 |
| Git / Linux | 分支、合并、SSH、日志、权限、常用命令 | 每天用，GitHub 有提交记录 |

### P1：加分项

- Docker / docker-compose / Nginx / gunicorn 或 uvicorn
- pytest / unittest、日志、压测（locust / ab）
- Wireshark、TCP 三次握手、TIME_WAIT、keep-alive
- 简单的 CI（GitHub Actions）

### P2：有余力再看

- Celery / RabbitMQ（知道“异步任务”解决什么问题即可）
- FastAPI（Django 熟了再学，不要同时学两个框架）
- K8s / 微服务（初级岗位不要求）
- 高并发系统设计（缓存、限流、幂等、消息队列的概念）

## 3. 毕设 → 简历：怎么讲才像“后端项目”

不要讲“我做了一个飞机大战”，要讲：

> “我实现了一个 C/S 实时通信系统：自定义 12 字节二进制协议，解决 TCP 粘包/拆包；asyncio 服务端 20 Hz 广播；Django + DRF 做登录和排行榜，MySQL 持久化，Redis ZSET 缓存；19 个协议边界测试，Wireshark 抓包验证，netem 做延迟/丢包实验。”

| 毕设模块 | 对应的后端能力 |
|---|---|
| 自定义二进制协议 + 粘包/拆包 | 网络编程、协议设计、边界处理 |
| asyncio 服务端 + 20 Hz tick | 并发、事件循环、性能 |
| Django + DRF 登录/排行榜 | Web API、认证、序列化 |
| MySQL 持久化 | 数据库设计、事务、索引 |
| Redis ZSET 排行榜 | 缓存、数据结构、性能 |
| 单元测试 + 压测 + 抓包 | 工程质量、排查能力 |

**简历上写真实数字**（测出来多少写多少）：

- 4 人 / 30 敌机 / 200 子弹，单核 8.9%
- 快照 ≈ 1974 B，20 Hz ≈ 39.5 KB/s
- 19 个协议边界用例
- Redis ZSET 排行榜 O(log N)

不要编数字。面试官会追问“怎么测的”。

## 5. 每周节奏（按每天 3 小时设计）

| 时间 | 做什么 |
|---|---|
| 周一至周五 | **3 h**：1.5 h 毕设 + 1 h 后端技能 + 0.5 h LeetCode/求职 |
| 周六 | 4 h：项目联调 / 写文档 / 补进度 |
| 周日 | 休息；晚上 1 h 复盘 |

**4 h/天怎么用**：只用来补前一天没完成的，不要连续一周 4 h；第 3 周崩了后面全乱。

**每周最低交付**：

- 毕设至少推进 1 个**能跑**的小功能
- LeetCode 至少 3 题（忙的时候 2 题）
- 周日 5 行复盘

**每周日写 5 行复盘**：

1. 这周完成了什么？
2. 哪个问题卡最久？怎么解决的？
3. 毕设进度到哪一步？
4. 求职技能补了什么？
5. 下周最重要的 3 件事？

如果只能每天 1 小时：优先 P0，时间表整体拉长，不要砍毕设核心。

### 5.1 时间不够时的砍单顺序

1. 砍游戏内容（敌机 / 弹幕 / BOSS）——论文不受影响
2. 砍第 7 周的 Nginx / 部署，只保留 Docker
3. LeetCode 从 5 题/周降到 3 题/周，1 月再补
4. 砍 README 美化，保留“怎么跑 + 架构图 + 测试结果”
5. **绝不砍**：asyncio + tick + 广播、压测、抓包、Django 登录/排行榜

## 6. 面试准备清单

### 6.1 算法 / SQL

- LeetCode Hot 100：数组、哈希、双指针、链表、二叉树、DP、回溯
- SQL 50：JOIN、GROUP BY、窗口函数、索引
- 目标：春招前 120~150 题；不是刷题机器，要能讲思路

### 6.2 八股（按岗位准备）

- **Python**：GIL、`list`/`dict` 底层、生成器、装饰器、上下文管理器、`async/await`、深浅拷贝、异常
- **Django**：请求生命周期、ORM、中间件、迁移、事务、N+1、缓存、认证/权限
- **MySQL**：索引（B+ 树）、事务、隔离级别、MVCC、`EXPLAIN`、慢查询、分页优化
- **Redis**：五种数据结构、持久化、缓存穿透/击穿/雪崩、分布式锁、ZSET 排行榜
- **HTTP/TCP**：三次握手/四次挥手、TIME_WAIT、keep-alive、状态码、HTTPS、粘包/拆包
- **系统设计基础**：限流、幂等、缓存、消息队列、负载均衡（知道概念和取舍）

### 6.3 项目讲解

准备三个版本：

- **30 秒**：一句话说清“做了什么、解决了什么问题、结果如何”
- **5 分钟**：架构图 + 协议 + 并发 + 数据库 + 缓存 + 测试
- **15 分钟**：深挖一个点，例如“粘包/拆包怎么处理”“20 Hz 广播怎么保证不卡”
